# ♠ allin · 德州扑克，对手是 LLM

一个可以直接在浏览器里玩的无限注德州扑克（No-Limit Texas Hold'em）。
**牌桌上的每一个 AI 对手都由真实的大语言模型扮演和操作** —— 默认接入
[OpenCode Go](https://opencode.ai/docs/go/)，也支持任意 OpenAI 兼容端点。

2–9 人桌，每个座位可以是 **AI**，也可以是 **人**：把邀请链接发给同一个 WiFi 下的朋友，
他打开就能入座，各自只看得到自己的底牌。

```
零 npm 依赖 · 无需构建 · node server/index.js 即可运行
```

---

## 快速开始

```bash
git clone git@github.com:noneowl/allin.git
cd allin
node server/index.js          # 或 npm start
```

启动后终端会打印本机和局域网地址：

```
  本机   → http://localhost:8787
  局域网 → http://172.16.0.198:8787   (en0)
```

用浏览器打开，先在建桌界面选人数（2–9）和每个座位是「人类」还是「AI」，点 **创建牌局并开局**。

> 想先看看界面长什么样？点右上角 **模型设置**，供应商选 **「离线演示（非 LLM）」**，
> 不需要 API Key 就能立刻打一局。**这只是界面预览**，不是真正的 AI —— 见下文说明。

## 多人同桌（局域网）

每个座位有一个专属凭证，**凭证决定了你能看到什么、能操作谁**。

1. 建桌时把某个座位设成「人类」→ 创建后点右上角 **邀请**
2. 把那一条链接发给朋友（同一个 WiFi 下，不用装任何东西）
3. 他打开就自动入座，**看到的是自己坐在最下方的牌桌**

建桌时有两种走法：

- **快速开始**：4 人桌，你 + 3 个 AI，立刻能打
- **自定义**：选人数（2–9），每个座位单独选「人类」或「AI」，AI 还可以挑角色

想拉人进来就点右上角 **邀请**：

- 已经有真人座位的，直接复制他的链接发出去
- 全是 AI 的桌子，面板里会列出每一个 AI 座位，点 **邀请人坐这里** 就把它让给真人，
  当场生成链接（会重新发一手牌）

安全边界由服务端强制，不是前端藏一下：

| 保证 | 实现 |
| --- | --- |
| 只看得到自己的底牌 | 每个 SSE 连接按自己的座位单独序列化牌局状态，别人的 `hole` 在服务端就是空数组 |
| 只能操作自己的座位 | 行动接口的座位号来自凭证，不是请求体 |
| 看不到牌堆里没发的牌 | 视图里根本没有 `deck` 字段，见下文穷举审计 |
| 不能替别人看到思考 | AI 的推理在**本手进行中根本不下发** |
| 一个 AI 不知道别人在想什么 | 每个 AI 座位用独立的供应商会话，且提示词里不含任何人的推理或桌边话 |
| 邀请链接不会被误发 | 列表里永远不含你自己的座位 —— 那是你的椅子，不是邀请 |

房主可以随时用 **新牌局** 改人数重开（会换一批邀请链接）。

如果某个受邀的人掉线，牌局会停在他那里；房主可以在行动栏点 **代为过牌/弃牌** 让牌局继续。

## 接入 OpenCode Go

[OpenCode Go](https://opencode.ai/docs/go/) 是 $10/月的订阅，提供一批主流开源模型的稳定访问。

1. 到 <https://opencode.ai/auth> 订阅 Go 计划并复制 API Key
2. 打开游戏的 **设置 → AI 供应商 → OpenCode Go**
3. 粘贴 API Key，选模型，点 **测试连接**
4. 保存

已经内置好了，无需手填地址：

| 项目 | 值 |
| --- | --- |
| Base URL | `https://opencode.ai/zen/go/v1` |
| 默认模型 | `glm-5.3-flash` |

### 三种协议自动切换

OpenCode Go 的模型分布在三种不同的 wire protocol 上，本作会**根据模型 ID 自动选择正确的端点**，
不需要你手动配置：

| 协议 | 端点 | 典型模型 |
| --- | --- | --- |
| OpenAI 兼容 | `/chat/completions` | `glm-5.3-flash`、`deepseek-v4.1-flash`、`kimi-k2.6`、`mimo-v2.5`、`hy3` |
| OpenAI Responses | `/responses` | `grok-4.6`、`gpt-5.6-luna`、`muse-spark-1.3-contributor` |
| Anthropic Messages | `/messages` | `qwen3.8-max`、`qwen3.8-flash`、`minimax-m3`、`minimax-m2.7` |

同时按 OpenCode 的要求发送 `x-opencode-session` 会话头（用于路由与 prompt 缓存）
和自定义 `User-Agent`（`dezhou-poker/1.0`）。

### 选模型：实测数据

单挑时 AI 占一半行动，延迟直接决定体验，所以我们实测过。同一个转牌局面（A♠Q♠ 坚果同花听牌
面对 60 下注）每个模型跑 4 次，预算 1500 token：

| 模型 | 平均延迟 | 有效输出 | 截断 | 隐藏思考 token |
| --- | --- | --- | --- | --- |
| **`glm-5.3-flash`** | **4.2s** | **4/4** | **0** | 0 |
| `longcat-2.0` | 21.2s | 4/4 | 0 | 864 |
| `deepseek-v4.1-flash` | 9.1s | 1/4 | 3 | 1397 |
| `mimo-v2.5` | 52.7s | 0/4 | 2 | 1500 |

结论：**默认用 `glm-5.3-flash`**（4 秒左右，零截断，输出稳定）。

⚠️ **推理模型要留足 token**。`deepseek-v4.1-flash` / `mimo-v2.5` 这类模型的思考 token
和你要的 JSON **共用同一个 `max_tokens` 预算**。预算不够时它们会思考完就没了，
返回空内容或半截 JSON —— 实测 `deepseek-v4.1-flash` 每次要思考约 1555 token，
即使把预算提到 3000 也仍会偶发截断，平均 10.8 秒。想用它们请把「最大输出 tokens」
调到 **3000 以上**。程序遇到截断会自动把预算翻倍重试（上限 8000），但那会白白多等一轮。

一局 5 人桌每手牌大约产生 8–20 次请求。

### 其他供应商

设置面板里还内置了 **OpenCode Zen、DeepSeek 官方、OpenRouter、本地 Ollama、任意 OpenAI 兼容端点**。
选「OpenAI 兼容端点」后自己填 Base URL + 模型名即可（vLLM、LM Studio、one-api 等都能用）。

### 环境变量（可选）

环境变量优先级高于设置面板里保存的值，适合不想把 Key 写进磁盘的场景：

```bash
export OPENCODE_GO_API_KEY=sk-...        # 或 OPENCODE_API_KEY
export DEZHOU_PROVIDER=opencode-go       # 供应商 id
export DEZHOU_BASE_URL=https://opencode.ai/zen/go/v1
```

配置保存在 `.data/config.json`（已 gitignore）。**API Key 只存在服务端**，
浏览器拿到的永远是掩码后的 `sk-a••••z9`。

## AI 是怎么决策的

这是本作最重要的设计约束：**没有本地启发式引擎**。

- 轮到 AI 行动时，服务端把完整的牌局状态序列化成结构化文本，连同该角色的性格设定一起发给 LLM
- LLM 必须返回严格 JSON：`{action, amount, reasoning, table_talk}`
- 服务端用 `Table.normalizeAction()` 校验动作合法性，非法就把错误回喂给模型重试（最多 3 次）
- 不同对手有**不同的性格卡**（紧凶 / 松凶 / 数学派 / 欺骗型 / 岩石 / 跟注站 / 稳健 / 平衡），
  每张卡都写死了四件事：**起手范围、激进度、下注尺度、弱点**。
  写得具体是关键 —— 只写"打得紧凶"会让模型退化成两种模式：早早弃牌，或者一路全下。
  现在每张卡都有具体数字（"加注到 3 个大盲""下注 50%–70% 底池""全下是极端动作"）
  和具体情境，打法才有多样性。
- **模型能看到历史**：提示词里带【本局战绩】（每个人的净盈亏、入池率、加注次数、
  摊牌/获胜次数）和【最近几手】（谁赢的、用什么牌、什么公共牌）。
  所以它会根据"这个人一直很松"或"这个人连输三把"来调整，而不是把每一手都当成第一手。
- **玩家可以发言**：侧栏有聊天框，你打的字会进提示词里的【玩家发言】一节，
  模型会像读现场马脚一样对待它 —— 可能信，也可能当成诈唬。

只有两种情况下不走 LLM，且都不构成"策略决策"：

1. **规则推导**：无需跟注、又不能下注时，只有"过牌"一个非弃牌选项 —— 没有决策可做，直接过牌
2. **故障兜底**：供应商彻底不可达时，取免费选项（能过牌就过牌，否则弃牌），并在牌桌实况里
   **红色高亮标注决策失败**，绝不伪装成正常决策

### 信息隔离（多人同桌时的关键）

一个会打字的 LLM 很自然会在推理里写"我中了三条，可以加注"—— 这句话一旦被对手看到，
或者被喂进另一个 AI 的提示词，牌局就毁了。所以：

- **推理在本手进行中不下发**。`Table.view()` 会把 `secret` 条目的 `text` 直接替换成 `null`，
  浏览器拿到的载荷里根本没有这段文字（打开 devtools 也看不到）。
- **封印是按手牌算的，不是按全局状态**。一旦某手结束，它的推理就永久可读 ——
  不会因为开了下一手又被重新封印（这正是之前的 bug：只有结算画面那几秒钟能看）。
- **推理不进入任何提示词**。`actionHistory()` 会过滤掉 `reason` / `error` 条目，
  以及 **AI 的** `talk`，只保留公共事件（谁下了多少注、发了什么公共牌）。
  唯一的例外是**人类玩家说的话** —— 那是玩家自己打的字，听回去正是桌边话的意义，
  也不可能泄漏另一个 AI 的底牌。
- **每个 AI 座位一个独立会话**。发往供应商的 `x-opencode-session` 是 `房间号-seat序号`，
  两个对手不会共享对话状态或 prompt 缓存血缘。
- **系统提示词里划了信息边界**：明确告诉模型它只知道公共信息和自己的底牌。

为了让桌边话还能玩，提示词只要求模型「不要直接念出自己的底牌」—— 虚张声势是允许的。

### 「AI 能看到我的牌，或者还没发的牌吗？」

**看不到。** 这条不靠"应该不会"，有两层可复核的验证：

1. **穷举审计**（`test/visibility.test.js`，8 个测试）。不抽样 —— 而是把 52 张牌全部枚举一遍，
   在每条街（翻前/翻牌/转牌/河牌）、每个 AI 座位上断言：

   - 提示词里出现的牌，**只可能是「该座位自己的 2 张 + 公共牌」**
   - 牌堆里**还没发的牌**一张都不出现
   - 人类玩家的底牌一张都不出现
   - 系统提示词**完全静态**（不同牌局状态下逐字节相同），所以状态不可能夹带进去
   - 客户端载荷里没有 `deck` 字段，未发的牌一张都到不了浏览器

2. **真实流量审计**（`node scripts/audit-wire.mjs`）。拦截发往 OpenCode Go 的**真实请求体**，
   逐字节检查。实际跑出来是这样：

   ```
   [✓] preflop 座位1  自己的牌=Q♦ 6♠  公共牌=[无]
         提示词里出现的牌: [Q♦ 6♠]
   [✓] river   座位2  自己的牌=6♣ 7♠  公共牌=[10♥ K♠ 10♦ 4♣ 8♣]
         提示词里出现的牌: [10♥ K♠ 10♦ 4♣ 8♣ 6♣ 7♠]
   ```

   座位 0（人类）的底牌从没出现在任何请求里。

想自己验一遍就 `node scripts/audit-wire.mjs`（会消耗几次真实调用）。

### 关于「离线演示（非 LLM）」

设置里的 `离线演示` 是一个明确标注的假 AI，用来在没有 Key 时预览界面。
它**不是** LLM，也**不是**默认选项，正常游玩请使用 OpenCode Go 或其他真实供应商。

### 桌边话

每个 AI 会输出 `table_talk`，以 `伊万：「这个注太小了，我加。」` 的形式出现在右侧实况栏里。
可以在设置里关掉。

## 牌桌功能

**引擎（完全实现，不是简化版）**

- 2–9 人桌，按钮位轮转，短筹码自动出局
- 无限注下注：最小加注跟踪、**短筹码全下不重开加注**、不足跟注的全下按跟注处理
- 完整的**边池**计算：多层 all-in 正确切分主池/边池，奇数筹码按庄家左手方向分配
- 未被跟注的下注自动退还
- 7 选 5 手牌评估（21 种组合），含 A-2-3-4-5 轮子顺子、轮子同花顺
- 筹码守恒：60 组种子 × 12 手随机模糊测试全程校验

**多人同桌**

- 每个座位独立选「人类 / AI」，AI 可挑角色
- 人类座位生成专属邀请链接，局域网内打开即入座
- 按座位的状态序列化：别人的底牌在服务端就不下发
- 每个玩家看到自己坐在最下方（座位视角按人旋转）
- 掉线显示「离线」，房主可代为过牌/弃牌

**界面**

- 椭圆牌桌：木质围栏 + 毛毡 + 金色内圈虚线，座位沿椭圆自动布局（2–9 人自适应）
- 真实的牌面：标准点数布局（10 的十字排列、J/Q/K 宫廷框、下半个花色倒置）
- 发牌/翻牌 3D 动画，AI 底牌在摊牌时**原地翻转**而不是替换 DOM
- 筹码堆按面额配色，加注滑杆 + 1/2 池 / 3/4 池 / 1 池 / 全下 快捷键
- **结算即复盘**：一手结束后没有任何挡住牌桌的弹窗，也不自动开始下一手。
  侧栏出现「本手结果」面板，列出每个人的底牌、最终牌型、盈亏；
  牌桌上**所有底牌同时翻开**（弃牌的会变暗），想看多久看多久，点「开始下一手」才继续
- **每个 AI 会点评结果**：一手结束后，每个 AI 用自己角色的一句话点评这手 ——
  得意、抱怨运气、点评对手、下战书。这些点评**并行请求**（不按顺序等），
  所以 8 人桌也只比单个多等一点点；不想花钱可以在设置里关掉「赛后点评」
- **玩家可以发言**：侧栏底部聊天框，你打的字会变成气泡冒在自己头像上，
  同时进入所有 AI 的判断依据
- AI 推理在**本手进行中显示为 🔒 封存**，本手结束才揭晓，
  且**已结束的手永远保持可读**，开下一手不会重新封印
- **桌边话直接冒在角色头像上**（气泡朝向远离牌桌的一侧，不挡公共牌），
  11 秒后自动消失，实况栏里同时保留带说话人的记录
- 键盘快捷键：`F` 弃牌、`C` 过牌/跟注、`R` 加注、`A` 全下、`空格` 下一手
- 零音频资源：所有音效用 Web Audio 现场合成

覆盖：

- **评估器**：9 种牌型分类、轮子顺子是最弱顺子、踢脚比较、7 选 5
- **边池**：单池、一层边池、多层边池、弃牌筹码留在池中、无人可赢的层被退还
- **状态机**：盲注、单挑时按钮位下小盲、大盲最后行动权、最小加注、
  短筹码全下不重开加注、超额下注退还、边池分配、按钮轮转
- **模糊测试**：60 个种子 × 每个 12 手随机合法动作，全程校验筹码守恒、无负筹码、牌局必定终止
- **供应商协议**：三种 wire protocol 的 URL / 请求头 / 请求体 / 响应解析、
  `x-opencode-session` 会话头、`max_tokens` 被拒后改用 `max_completion_tokens` 重试、
  401 错误透传、模型列表解析
- **AI 决策健壮性**：推理模型截断后自动扩容重试（400→800→1600，上限 8000）、
  半截 JSON 也算截断、非法动作回喂重试、超额加注夹取而非报错、401 不重试
- **座位隔离**（多人同桌的核心保障）：任何视角都拿不到别人的底牌、
  提示词里不含别人的底牌 / 推理 / 桌边话、实时推理被封印且载荷里没有明文、
  本手结束后才解封、每个 AI 座位使用独立的供应商会话
- **可见性穷举审计**：52 张牌全部枚举，逐条街断言提示词里只可能出现
  「自己的牌 + 公共牌」，未发的牌和别人的牌一张都不出现；系统提示词逐字节静态
- **结算复盘**：手牌结束后所有底牌翻开（含弃牌的）、玩家发言能进 AI 提示词、
  AI 的桌边话仍然互相隔离、赛后点评会为每个 AI 座位生成一条并标注所属手牌、
  赛后点评可以关掉、角色卡四个字段都不许是敷衍的一句话

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/bootstrap` | 配置（Key 已掩码）+ 供应商目录 + 角色名单 + 局域网地址 |
| GET | `/api/events` | SSE 事件流，**按凭证所在座位单独出状态** |
| GET | `/api/models` | 从供应商拉取模型列表 |
| POST | `/api/config` | 保存设置 |
| POST | `/api/config/test` | 连通性测试 |
| POST | `/api/room` | 建桌开局 `{seats, players[], rules}`，返回座位凭证与邀请链接 |
| POST | `/api/room/join` | 用房间号 + 凭证（或不带凭证取空位）入座 |
| GET | `/api/room` | 当前房间信息 + **我这个座位视角**的状态 |
| GET | `/api/room/invites` | 邀请链接 + 可认领的 AI 座位（仅房主） |
| POST | `/api/room/seat` | 把某个座位改成真人 / AI 并重新发牌（仅房主） |
| POST | `/api/room/say` | 玩家发言 `{text}`，会进入 AI 的提示词 |
| POST | `/api/room/action` | 我行动 `{action, amount}`，座位号取自凭证 |
| POST | `/api/room/next` | 下一手 |
| POST | `/api/room/restart` | 重开一局（仅房主，保留座位和链接） |
| POST | `/api/room/force` | 代离线玩家过牌/弃牌（仅房主） |
| POST | `/api/room/retry` | 重试当前 AI 决策 |
| POST | `/api/room/cancel` | 取消进行中的 AI 请求 |

座位凭证通过 `?room=&token=` 或 Cookie 传递（邀请链接优先）。`/api/room/*` 里除建桌和入座外，
全部需要有效凭证，且座位号由凭证决定 —— 请求体里没有座位号可以伪造。

`amount` 的语义是 **raise-to**：你希望自己在本街投入的**总金额**，不是本次增量。
提示词里对模型也是这么约定的，服务端会再夹取到合法区间。

## 说明

- 牌局存在服务端内存里，重启即清空；凭证放在浏览器 sessionStorage + Cookie
- 默认绑定 `0.0.0.0`，同网络可访问。只想自己玩就 `HOST=127.0.0.1 node server/index.js`
- 局域网邀请做到这个程度就够了。想跨互联网联机需要一个中继/公网地址，
  现在的代码没做，别把 `8787` 端口直接暴露到公网
- AI 每次决策需要一次真实的 LLM 请求，用推荐的 `glm-5.3-flash` 大约 4 秒一步
- 换推理模型（如 `deepseek-v4.1-flash`）会更慢，记得同时把 `maxTokens` 调大
